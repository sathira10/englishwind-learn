## Agentic-coding practices taken from the list

Kept: 1 (the loop), 2 (spec template), 3 (one-sentence PRs), 4 (logic before UI, thin slices),
5 (state in repo), 6 (short router files), 7 (Pitfalls grows only on repeat mistakes), 8 (rules
as scripts and hooks), 9 (protected truth tests), 10 (reference + property + mutation tests),
11 (agent proposes properties, Sathira approves), 12 (named failure modes, rewritten for this
app), 13–14 (numbers: a metrics script), 15 (mid-tier default, as a workflow note only).

Dropped: the audio-specific items in 12 (audio thread, pluginval/auval, host save/restore).

The named failure modes for review (`docs/review.md`): a route that serves a lesson, Vimeo ID or
file without a grant check; an R2 key or signed URL reaching the client; approve-twice on a bank
transfer; D1 work that needs atomicity done outside `batch()`; `/admin` trusting the Access
header without verifying the JWT and the role; secrets in `PUBLIC_*` or the bundle; dates and
access periods without a timezone (Asia/Colombo) or with months instead of the 3-year rule; LKR
amounts as floats instead of integer cents; personal data in logs.

Testing (`docs/testing.md`): Vitest for unit and Worker tests (`@cloudflare/vitest-plugin`
so D1 and R2 are real), `fast-check` for property tests from the first domain slice, Playwright
for one smoke flow. Mutation
testing (Stryker) is added with the first domain slice (grants), scoped to `src/domain/`, and
runs weekly in CI, not on every PR. Adding it now would mutate an empty folder.

## Review before building (6 Nov)

- `@cloudflare/vitest-pool-workers` is deprecated and only supports Vitest 4. Its replacement,
  `@cloudflare/vitest-plugin`, supports Vitest 5, so the repo uses that with Vitest 5 as
  web-scaffold does.
- `typescript-eslint` supports TypeScript below 6.1, so TypeScript stays on 5.9. ESLint stays on
  9 and React Router on 7, as in englishwind-web and web-scaffold.
- `tokens.css` follows `prefers-color-scheme` unless the root says otherwise, so `index.html`
  sets `data-theme="light"` to keep the launch light-only.
- With the Cloudflare Vite plugin the environment is chosen at build time
  (`CLOUDFLARE_ENV=staging vite build`), and `wrangler deploy` reads the config the build writes.
- fast-check moves to the grants slice with Stryker: the scaffold has no logic for a property to
  hold over.
- The reference guard stops accidental edits and Claude's file tools. It can't stop an agent that
  writes the approval trailer itself through the shell. ADR 0006 says so, and CODEOWNERS on
  `tests/reference/` closes the gap once there is a GitHub remote.

## Steps

Each step is one local commit on `main` (no remote yet, so no PRs; the PR template is ready
for when there is one).

1. `chore: init repo with agent guides and plans` — git init, AGENTS.md, CLAUDE.md,
   CLAUDE.local.md, README, `plans/`, `docs/`, ADRs, `.gitignore`.
2. `chore: add vite react worker toolchain` — package.json, configs, client shell, Hono worker
   with `/api/health`, wrangler envs.
3. `chore: add design system from englishwind-web` — copy, Tailwind wiring, `check-tokens`,
   `ds:check`.
4. `test: add unit, reference and e2e layers` — health tests in each layer, reference guard,
   `.claude/settings.json`, git hooks.
5. `ci: add check and deploy workflows` — ci.yml, deploy.yml, PR template, metrics script.

Done when `pnpm install && pnpm check` passes, `pnpm dev` serves the shell with `/api/health`
returning `{ ok: true }`, `wrangler deploy --dry-run --env staging` passes, and a commit that
edits `tests/reference/` without the trailer is refused.

Not in this plan: auth, the schema, any screen beyond a placeholder, creating Cloudflare
resources or GitHub repos.
